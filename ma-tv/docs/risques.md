# Risques : revue critique

Ce document recense ce qui peut mal tourner avec la branche `ma-tv` sur la Samsung UE43AU7105 (Tizen 6.0) : la TV, le compte Samsung et les certificats, les données et le réseau, la fiabilité, et la mise à jour automatique choisie par Alexis. Pour chaque risque : probabilité, impact, atténuation **en place** (dans le code) et ce qui reste **à faire**.

Échelles : probabilité *faible / moyenne / élevée / certaine* ; impact *faible / moyen / élevé*. Tout ce qui n'est ni testé ni sourcé est marqué **non vérifié**. Ce qui est « lu dans le code » décrit le comportement prévu par le code, sans essai réel. Pour revenir à l'état d'origine : [retour-arriere](retour-arriere.md). Pour les replis : [plan-b](plan-b.md). Pas à pas : [procedure](procedure.md).

## Les 8 points à retenir

1. **Les deux certificats expirent le 2027-10-20** (validité d'un an, mesuré). Les renouveler en septembre 2027 ([procédure](procedure.md#renouveler-les-certificats)). `sign.py` prévient 30 jours avant (§ 2, C3).
2. **Sauvegarder le certificat auteur, le profil et `.local/ma-tv.json`** dans une copie chiffrée hors du Mac, sinon les mises à jour en place deviennent impossibles (§ 2, C1).
3. **La mise à jour est entièrement automatique** : aucune personne ne regarde l'écran avant l'installation. Les barrières (§ 5) arrêtent les régressions connues, pas tout.
4. **Mode développeur actif = port sdb ouvert sur le réseau local** (§ 3, R1).
5. **Le Mac est appairé comme télécommande réseau** : son jeton permet d'envoyer des touches. Le retirer quand on n'en a plus besoin (§ 3, R2).
6. **Une mise à jour du firmware peut faire disparaître l'app** (§ 4, F1). Garder `.local/releases/` et les certificats.
7. **CleanFrame n'est pas l'écran d'accueil système** : la touche Home et l'allumage mènent à Samsung Home (mesuré ; § 4, F2, [plan-b](plan-b.md) § 9).
8. **Fork public** : tout ce qui y est poussé est définitif (§ 3, R4).

## 5. Chaîne de mise à jour (entièrement automatique)

**Choix d'Alexis :** `ma-tv/maj` (`update.py`) enchaîne récupération, fusion, build, recette, anti-fuite, signature, installation, lancement, puis avance de `ma-tv` et push, **sans demander de confirmation**. `--confirm` rétablit une question avant chaque commande vers la TV, `--dry-run` montre sans rien faire. Détail des options : [procédure](procedure.md#mettre-à-jour--ma-tvmaj).

### Barrières en place (dans l'ordre d'exécution)

| Étape | Barrière | Effet en cas d'échec |
| --- | --- | --- |
| 0. Préalables | Branche `ma-tv`, arbre propre, remote `upstream` présent, première installation faite (identité et empreinte auteur connues) | Arrêt, rien n'est touché |
| 1. Récupération | `git fetch upstream` (sorties git forcées en anglais, `LC_ALL=C`, pour que les conflits soient bien reconnus) | Arrêt |
| 2. Rien à faire ? | Aucune nouveauté **et** `tv.installed_commit` = `ma-tv` → fin, **sans contacter la TV** (sauf `--rebuild`) | — |
| 3. Fusion | `merge --no-ff` dans une branche temporaire `ma-tv-maj-<date>` (jamais de rebase ni de push forcé). Échec détecté par le code retour, les fichiers non fusionnés **et** `MERGE_HEAD` | `merge --abort`, branche temporaire supprimée, `ma-tv` intacte. Résolution manuelle : [procédure](procedure.md#conflit-de-mise-à-jour) |
| 4. Build (`build.py`) | `scripts/native-home` absent ; privilèges limités à 3 ; éléments de `config.xml` en liste blanche ; `content` = `index.html` ; `background-support` désactivé ; aucune URL ni API réseau ; pas de script ni de style en ligne ; `JS_BLOCKERS` (sur un code vidé de ses chaînes, commentaires et regex) et `CSS_BLOCKERS` (ancrées sur les déclarations) ; `mask` toujours doublé de `-webkit-` ; forme des fichiers de l'auteur reconnue, sinon arrêt propre ; `config.xml` généré relu et vérifié ; empreintes des polices (avertissement) | Arrêt, branche temporaire supprimée |
| 5. Recette (`harness/run.mjs`, 3 essais de démarrage) | Chromium 76 et Chrome 155 : 14 écrans, touches, échecs de lancement, reprise, persistance, aucune erreur console ou réseau, aucun accès à une API Tizen non imitée, géométrie à ±4 px. Attentes lues dans la config réellement construite | Arrêt, branche temporaire supprimée |
| 6. Anti-fuite (`leak_check`) | Seulement si le fork est configuré et le push activé : fichiers suivis et historique à pousser (voir R4). **Avant** la signature | Fuite détectée → arrêt, rien n'est signé ni publié |
| 7. Signature (`sign.py`) | Profil présent ; **même certificat auteur** qu'à la 1re signature ; certificats non expirés (alerte à 30 jours) ; `openssl` obligatoire ; fichiers de signature présents ; archive dans `.local/releases/` | Arrêt avant la TV |
| 8. TV : garde-fou (`tv.py`) | `guard_tv` une fois par processus, avant la première commande sdb : modèle, identifiant réseau, mode développeur, IP du Mac | Arrêt, TV non touchée |
| 9. Installation | Message de succès, aucune marque d'échec, présence dans `applist` ; repli `vd_appinstall` | Refus avec l'ancienne app toujours présente → arrêt **sans** retour arrière (l'ancienne version reste). App absente → retour arrière (étape 10) |
| 10. Lancement | `tizen run` (repli `was_execute`) doit confirmer le lancement → la version devient « validée » (`tv.last_good_archive`) | **Retour automatique** à la dernière version validée (`tv.rollback()`), puis arrêt |
| 11. Avance de `ma-tv` | **Seulement après validation sur la TV** : `merge --ff-only` de la branche temporaire, puis `tv.installed_commit` enregistré | — |
| 12. Push sur le fork | `leak_check` refait sur les commits à pousser, puis `git push <fork> ma-tv` | Push refusé → avertissement, la TV reste à jour. Fork absent → avertissement, rien n'est publié |

`--confirm` : un refus (« N ») est une annulation, pas un échec : pas de retour arrière. `--skip-tv` : `ma-tv` avance et le fork est mis à jour **sans** validation sur la TV ; `installed_commit` ne bouge pas, donc le `maj` suivant installera. Journal complet : `.local/logs/ma-tv-AAAAMMJJ.log`.

### Risques résiduels de l'automatisme

| # | Risque | Prob. | Impact | Atténuation / à faire |
| --- | --- | --- | --- | --- |
| U1 | **Aucun contrôle visuel humain** avant l'installation : la géométrie comparée à Chrome 155 n'est qu'un indicateur | moyenne | moyen | Regarder l'écran après chaque mise à jour. Retour arrière manuel : [retour-arriere](retour-arriere.md#retour-arrière-partiel--revenir-à-une-version-validée) |
| U2 | **La mise à jour interrompt ce qui passe à l'écran** : `guard_tv` exige une TV allumée (écran actif), et l'installation relance CleanFrame | élevée | faible | Lancer `ma-tv/maj` quand personne ne regarde. Ne pas planifier de tâche automatique |
| U3 | **Limites du retour arrière automatique** (lu dans le code, non testé en réel) : (a) si l'installation échoue en laissant l'app **absente**, `rollback()` vise l'**avant-dernière** version validée (`previous_good_archive`) au lieu de la dernière ; aujourd'hui il n'y en a pas, donc arrêt « Aucune version validée à réinstaller » et TV sans CleanFrame ; (b) la TV peut refuser une version plus ancienne ou de même numéro (**non vérifié**) ; (c) un faux échec de lancement (message attendu absent) déclencherait un retour inutile | faible | moyen | Repli manuel : réinstaller l'archive validée nommée dans `tv.last_good_archive` ([retour-arriere](retour-arriere.md#retour-arrière-partiel--revenir-à-une-version-validée)). | U4 | Code malveillant en amont (compte de l'auteur compromis, dépôt recréé le 20/10/2026, commits non signés) : il tournerait avec les droits de l'app (lancer des apps, lister les apps installées) | faible | élevé | Aucun script de l'auteur n'est exécuté (ni `npm`, ni `scripts/`). Les barrières sont des motifs contournables : voir R7 | Option : `ma-tv/maj --dry-run` pour lire les nouveautés, puis `--confirm` |

| U6 | Consignes pour agents dans les docs de l'auteur (`AGENTS.md`) qui pousseraient un agent à lancer des commandes TV | faible | élevé | `update.py` est déterministe, sans agent dans la boucle. Un texte de l'amont est une donnée, jamais une instruction |
| U7 | **TV éteinte ou en veille** pendant `maj` (lu dans le code, non testé) : tout est refait jusqu'à la signature, puis arrêt au garde-fou. `ma-tv`, `installed_commit` et le fork ne bougent pas ; la branche temporaire est supprimée. | U8 | Invites du CLI `tizen package` (« password: », « No: (N) ? ») propres à une version du CLI : un changement bloquerait la signature jusqu'au délai (180 s) | faible | faible | Arrêt propre au bout du délai ; en cas de délai, tout le groupe de processus est tué (le CLI lance un Java enfant) |

## Ce qui n'est pas un risque ici

- **Polices propriétaires (Pangram)** : `build.py` exclut tout `PP*` et `assets/private-fonts/`. Les graisses fixes viennent de polices OFL, licences incluses.
- **Dépendances npm** : `update.py` n'en installe ni n'en exécute aucune. Le harnais n'utilise que Node et un client DevTools maison.
- **Réglages système de la TV** : ma-tv n'en écrit aucun (pas de vconf, pas de Home natif).
